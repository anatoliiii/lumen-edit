# Ревью FIM и Next Edit — 24 октября 2026

Область: `src/inline_completion/*`, интеграция в редактор, история пользовательских изменений. Это ревью локального кода; качество модели на реальных запросах и контракт актуального API отдельно не проверялись.

## Исправлено в этой правке

- Вместо сырого unified diff в узком Label — отдельный модуль просмотра: номера строк исходного файла и результата, фон удалённых/добавленных строк, счётчики, горизонтальная и вертикальная прокрутка без переноса кода. Кнопки находятся вне прокрутки, метрики свёрнуты. Окно открывается по центру, имеет крестик и возвращает фокус редактору после решения.
- `next_edit::Controller::invalidate` теперь отсоединяет приёмник: уже готовый ответ отменённого запроса не может вновь открыть предпросмотр при возвращении курсора на прежнее место.
- Очистка предпросмотра проверяет сохранённые id/version/cursor/expected через `Preview::is_current`. Раньше сравнивались текущие параметры документа с текущими параметрами того же документа, поэтому изменение активного документа не убирало устаревшее окно. Применение старой версии и раньше блокировалось.
- Во время ожидания Next Edit запрашивается следующий кадр; результат больше не зависит только от последующего пользовательского ввода.
- Ожидающий или открытый Next Edit блокирует запуск FIM; при запуске Next Edit убирается прежний ghost text.

## Оставшиеся замечания

### P1. Next Edit не подчиняется бюджету и квотам FIM

`src/inline_completion/mod.rs`, `Controller::tick` → `next_edit::Controller::launch`: проверяются разрешение проекта и пауза, но нет проверки requests_per_minute, requests_per_session, session_budget_usd. Они реализованы только в FIM `controller::Controller::launch`. Повторные ручные вызовы Next Edit продолжают отправляться после исчерпания этих ограничений.

Предложение: общий scheduler/accounting для обоих режимов, резервировать бюджет до HTTP, учитывать завершение и отмену, применять общий backoff 429. Настройки должны явно показывать область действия лимита. Проверки: исчерпанный бюджет не вызывает HTTP; отмена до отправки возвращает резерв; отправленная отмена учитывается консервативно.

### P1. Границы CRLF-файла считаются неправильно

`src/inline_completion/next_edit.rs`, `file_line_char_start`: `str::lines()` удаляет `\r\n`, а к длине каждой строки прибавляется только один символ. Для `a\r\nb\r\nc` начало третьей строки получается 4 вместо 6. Область замены смещается и может разрезать соседнюю строку; показываемый номер строки наследует эту ошибку.

Предложение: использовать Rope::line_to_char или split_inclusive('\n') с реальными длинами. Проверки: LF/CRLF, Unicode, пустой файл, последняя пустая строка, отсутствие завершающего перевода строки. Отдельно сохранять стиль окончаний строк при разборе ответа модели.

### P1. Next Edit принимает ответ без проверки завершённости и синтаксиса

`src/inline_completion/next_edit.rs`, `request` и `Controller::poll`: читается content без проверки finish_reason; после проверки Markdown-ограждения сразу строится замена. Для FIM есть `validation::acceptable`, но для замен она не вызывается. Даже формально закрытый блок может содержать некорректный код. Жёсткие 256 выходных токенов требуют воспроизвести до 15 строк и могут не вместить область.

Предложение: отдельно валидировать replacement на копии полного документа, сравнивать синтаксические ошибки до/после, отклонять незавершённый ответ. Для неоднозначных результатов показывать явное предупреждение в просмотре. Размер области и выходной бюджет связывать между собой. Не применять insertion-validator без адаптации: он рассчитан на вставку, а не удаление/замену.

### P2. История редактирования искажает позиции и не соблюдает свой размерный предел

`src/inline_completion/next_edit.rs`, `build_request`: абсолютное символьное смещение `h.start` превращается в `min(start, 80)` пробелов. Это не номер строки и не корректный контекст исходного diff; большинство изменений далеко от начала файла получают одинаковый искусственный отступ.

`src/app/document.rs`, `absorb_edits`: ветки объединения typing/deleting делают continue до ограничения размера; единичная запись не ограничена; total вычисляется один раз перед удалением записей. В результате история либо растёт выше 16 KiB, либо удаляет больше записей, чем требуется.

Предложение: хранить ограниченные контекстные hunks с настоящими строковыми позициями, ограничивать каждую запись и суммарный объём после любого слияния, пересчитывать/вычитать размер при удалении. Проверки: длинная последовательность ввода, большая вставка, Unicode, последовательные удаления.

### P2. FIM молча ограничивает настройку max_tokens значением 32

`src/inline_completion/provider.rs`, `InceptionFimProvider::body`: max_tokens.clamp(1, 32), тогда как OpenRouter допускает до 512. Пользовательское значение выше 32 для Mercury не действует. Это ограничивает возможную длину подсказки; влияние на качество требует отдельного сравнения на примерах.

Предложение: явные профили «короткая подсказка» и «несколько строк», согласованные пределы в настройках и payload. Оценивать acceptance rate и задержку на одинаковом наборе Rust/Go/Python-примеров до изменения дефолта.

### P2. Метрики задержки FIM перестают отражать последние запросы

`src/inline_completion/controller.rs`, `poll`: push_back + truncate(128) сохраняют первые 128 измерений, удаляя новые. После заполнения окна p50/p95 застывают. `launch` берёт debounce_ms из всего времени since.elapsed(), поэтому ручной запрос после долгой паузы включает пользовательский простой в задержку.

Предложение: удалять старые элементы через pop_front; отдельно измерять ожидание debounce, очередь, контекст, HTTP и время до отображения. Проверки: 129-й образец заменяет первый; ручной запрос после минуты простоя не добавляет минуту к latency.
